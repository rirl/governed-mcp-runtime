== Branch Objective

The purpose of this branch is to mature the governed MCP runtime from the
initial prototype into a production-quality engineering runtime that provides:

* Deterministic Docker builds.
* Reproducible runtime environments.
* Automated runtime verification.
* A reproducible VS Code development environment.
* A stable execution platform for governed engineering repositories.

Completion of this work will allow GAE-0001 within the Awake in Omelas
repository to resume using a fully reproducible runtime.

== Engineering Philosophy

The following principles guide this branch.

=== Reproducibility First

Given identical repository contents, the runtime should build into an
identical execution environment.

No dependency should be resolved from an unbounded "latest" version.

=== Engineering Before Expansion

The objective is to strengthen the execution platform before expanding its
capabilities.

A reliable runtime provides greater long-term value than additional features.

=== Small, Reviewable Changes

Implementation should proceed through a sequence of focused commits.

Each commit should represent a complete, reviewable engineering improvement.

=== Verify Before Proceeding

Every engineering enhancement should be validated before additional work
begins.

Verification is part of implementation rather than a later activity.

== Current Assessment

GAE-0001 successfully validated the repository governance model and exposed a
runtime engineering defect.

The failure was isolated to the runtime image rather than the target
repository.

Investigation showed that the Docker image currently resolves floating
dependencies during every build.

Consequently, rebuilding the runtime does not guarantee equivalent runtime
behavior.

The immediate engineering priority is therefore runtime stabilization rather
than continuation of governed artifact execution.

== Phase 1 — Runtime Stabilization

Objective::

Establish a deterministic runtime image.

Planned Work::

* Pin the Docker base image.
* Pin Python dependencies.
* Pin Node dependencies.
* Eliminate floating package resolution.
* Produce repeatable Docker builds.

* Locked dependency graph

Completion Criteria::

* Successful runtime startup.
* Successful OpenAPI endpoint.

== Engineering Notes

This section records engineering discoveries made during implementation.

Notes capture implementation decisions, observations, and revised approaches.

They are intentionally separate from governance records.

=== EN-0001 — Runtime Reproducibility

GAE-0001 exposed that the governed runtime image was not reproducibly built.

Floating Python and Node dependencies allowed subsequent image rebuilds to
resolve incompatible dependency graphs.

Future runtime images will explicitly pin all externally resolved runtime
dependencies.

Status::

OPEN

=== EN-0002 — Development Environment

The preferred engineering environment will become a VS Code Dev Container.

The Dev Container will provide a reproducible operator workspace while the
governed runtime itself continues to execute as an independent Docker
container.

Status::

PLANNED

=== EN-0003 — Runtime Architecture

The separation of repositories proved valuable during GAE-0001.

The runtime engineering defect was isolated entirely within the
`governed-mcp-runtime` repository without requiring changes to the governed
target repository.

This validates the architectural decision to separate runtime engineering
from governed project repositories.

Status::

OBSERVED
