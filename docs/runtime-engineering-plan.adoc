== Motivation

The initial Governed MCP Runtime successfully demonstrated the end-to-end
execution path:

Governed Launcher →
Docker →
Filesystem MCP Server →
MCPO →
Open WebUI.

Subsequent validation exposed that the runtime depended upon floating package
versions obtained during image construction.

A later rebuild produced an incompatibility between the Python packages
`mcpo` and `mcp`, causing the runtime to fail before startup.

Version 0.2 focuses on eliminating this class of failure by making runtime
construction deterministic.

== Objectives

Phase 1 seeks to establish a reproducible runtime foundation.

Objectives include:

* deterministic Docker image construction
* explicit dependency policy
* reproducible Python runtime
* reproducible Node runtime
* reproducible Docker build process
* successful end-to-end runtime validation

== Guiding Principles

The runtime should evolve using normal engineering practice.

Engineering observations should drive implementation.

Validation should accompany each significant modification.

The runtime should become progressively more deterministic rather than more
complex.

== Engineering Decisions

=== Repository-root Docker Build Context

Status::

COMPLETE

The Docker build now uses the repository root as its build context rather than
the Dockerfile directory.

Benefits:

* simpler COPY operations
* future-proof repository layout
* consistent build semantics
* easier addition of future build artifacts

=== Dedicated Build Workspace

Status::

COMPLETE

Temporary build artifacts are staged within:

----
/build
----

rather than relying on `/tmp`.

The workspace is removed before the image is finalized.

=== Dependency Policy

Status::

COMPLETE

Python dependency policy has been separated into:

----
docker/mcp/constraints.txt
----

This allows dependency versions to evolve independently from Docker build
mechanics.

Current pinned versions:

----
mcpo==0.0.20
mcp==1.28.1
----

=== Build Wrapper

Status::

COMPLETE

The build wrapper now:

* discovers the repository root
* invokes Docker BuildKit
* prints build configuration
* performs repository-root builds

The wrapper has become the canonical image construction interface.

== Engineering Observations

=== EO-0001

The original runtime failure was caused by dependency drift rather than defects
within the governed launcher.

=== EO-0002

Separating dependency policy from Docker implementation significantly improves
runtime maintainability.

=== EO-0003

Repository-root Docker builds provide a cleaner long-term architecture than
Dockerfile-relative contexts.

=== EO-0004

The build wrapper has evolved from a convenience script into the canonical
runtime construction interface.

=== EO-0005

Explicit validation after each engineering change substantially reduced
debugging effort.
